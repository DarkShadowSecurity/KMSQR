## Remaining — external or organizational dependencies

These are deliberately **not** claimed as done because they cannot be satisfied by
this repository alone:

| Item | Why it's external | Path |
|---|---|---|
| **FIPS 140-3 validated module** | Requires a lab/vendor validation process; liboqs is not FIPS-validated. | Use PKCS#11 HSM custody for a validated Root-KEK boundary; see [COMPLIANCE.md](COMPLIANCE.md). |
| **SOC 2 Type II / ISO 27001 certification** | Requires an independent assessor and org-wide controls (HR, physical, change mgmt). | Control mapping provided in [COMPLIANCE.md](COMPLIANCE.md) as audit input. |
| **Image signing + SLSA provenance** | Repo policy pins actions/tools by digest; must be wired with maintainer-verified SHAs, not fabricated offline. | Ready-to-enable procedure in [`../deploy/RELEASE.md`](../deploy/RELEASE.md). |
| **KMIP / PKCS#11 *client provider*** | A large protocol surface; current integration is the REST API + SDKs. | Candidate next major feature; REST API covers programmatic use today. |
| **Client SDKs (Java/Go/.NET)** | Distribution + per-language maintenance. | OpenAPI is auto-generated by FastAPI (`/docs`); SDKs can be generated from it. |
| **Penetration test / formal crypto review** | Requires an external party. | Threat model ([THREAT_MODEL.md](THREAT_MODEL.md)) scopes the engagement. |

## Posture summary

The product is **functionally enterprise-ready** for deployment behind your own
controls: identity, least-privilege multi-tenant authorization, SSO, full key
lifecycle, post-quantum crypto with custody options up to HSM, HA, observability,
DR, and a documented security posture. The remaining items are **certifications
and integrations that require external parties or organizational processes** —
the software provides the hooks (HSM custody, control mappings, SBOM, OpenAPI,
threat model) needed to pursue them.
